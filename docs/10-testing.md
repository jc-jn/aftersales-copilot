# 10. 测试方案

## 1. 测试金字塔

- Java 单元测试：状态机、资格规则、金额、幂等、权限。
- Python 单元测试：Schema、检索过滤、Prompt 输出验证、工具绑定。
- 集成测试：MySQL/Redis/RabbitMQ/Qdrant/MinIO 和内部 API。
- 契约测试：Java/Python JSON、SSE、MQ envelope。
- E2E：核心售后流程。
- AI 评测：检索、引用、结构化分类、安全和成本。

## 2. Java 必测用例

### 2.1 状态机

- 每个合法转换成功并增加 version。
- 每个非法跨越（如 `SUBMITTED → RESOLVED`）失败。
- 仅退款不进入退货状态。
- 退货退款/换货/维修没有退货检查不能完成。
- CLOSED 后所有业务命令失败。
- 并发两个命令只有一个版本更新成功。

### 2.2 资格和金额

- 四类窗口边界：截止前 1ms、截止点、截止后 1ms。
- 已退款金额扣减正确，不能超过订单项实付。
- SKU/商品/类目/全局规则优先级。
- 未拆封要求、质保期、取消订单。
- Java 结果与 seed 政策文档保持一致。

### 2.3 幂等

- 相同 Key + 相同请求返回相同执行结果。
- 相同 Key + 不同请求报冲突。
- 两线程同时确认只生成一个 refund/return order。
- MQ 重复消息只保存一次分析结果。
- 回调超时重试不会重复状态跳转。

### 2.4 权限

- 用户不能访问他人订单/工单/附件。
- 客服不能处理其他客服工单，转派后旧客服权限立即变化。
- AI 内部接口拒绝用户 JWT。
- HMAC 错误、过期 timestamp、重复 nonce 被拒绝。

## 3. Python 必测用例

- 无效枚举、confidence 越界、超长字段被 Pydantic 拒绝。
- Tool ID 与当前工单不一致时拒绝调用。
- 无证据时 `needs_human=true`。
- Provider 返回非 JSON 时只修复一次。
- 流开始后主模型失败，不切换 Fallback 拼接答案。
- 文档部分向量写入失败时清理当前 indexVersion。
- 过期/错误 scope 的 chunk 不被召回。
- 提示注入样例不能获得隐藏数据或写工具。

## 4. 契约测试

维护 JSON Schema/OpenAPI 作为事实来源：

- Java producer 契约测试生成 `ticket.ai.analyze.requested.v1` fixture。
- Python consumer 使用同一 fixture 验证。
- Python 回调 fixture 由 Java 反序列化测试。
- SSE parser 使用拆包、半行、多个事件、Unicode、心跳、错误结束用例。
- schemaVersion 未知时消费者必须拒绝而非猜测解析。

## 5. E2E 场景

### E2E-01 仅退款

用户登录→查看订单→创建仅退款工单→AI 分析→自动分配→客服审核提案→用户确认→Java 模拟退款→RESOLVED→评价→CLOSED。

### E2E-02 退货退款

创建→请求补充→用户补充→提案→确认→填写退货物流→客服收货检查→模拟退款→结案。

### E2E-03 换货

确认换货→退货→检查通过→生成补发记录和物流→完成。

### E2E-04 维修

确认维修→寄回→检测→维修→寄回用户→完成。

### E2E-05 降级

关闭 Fake/真实 AI 服务→创建工单仍成功→客服人工处理→最终结案。

### E2E-06 安全

用户 A 修改 URL 访问用户 B 工单→403；重复确认提案→只有一个执行结果；Prompt 注入→转人工且无敏感信息。

## 6. 测试数据

至少准备：

- 1 管理员、3 客服、5 消费者。
- 3 类商品：耳机、键盘、手机；每类 2 个 SKU。
- 每用户 3～5 个不同状态订单。
- 正在窗口内、窗口外、部分退款、过保、未签收等边界订单。
- 40+ RAG/AI 标注用例。

测试账号和密码只用于 local/demo，并在云部署时通过初始化脚本覆盖。

## 7. 性能测试

使用 k6/JMeter：

- 50 并发查询工单列表和详情，记录 P50/P95/P99。
- 10 并发创建工单，验证同一订单项防重。
- 20 并发领取同一工单，只有一个成功。
- 10 并发确认同一提案，只有一个执行记录。
- SSE 使用 Fake Provider 测 20 并发流；真实模型性能只记录，不做虚假容量结论。

性能报告必须写机器配置、数据规模、测试脚本和结果，不只写“支持高并发”。

## 8. 完成门槛

- 所有核心用例通过。
- Java 状态机/资格/幂等不存在跳过测试。
- Python 评测结果有版本和日期。
- 无高危硬编码密钥。
- Docker demo E2E 至少完整跑通一次并录屏。
