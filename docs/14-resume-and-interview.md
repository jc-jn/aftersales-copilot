# 14. 简历与面试说明

## 1. 项目描述模板

> AfterSales Copilot 是一个面向 3C 电商的智能售后工单平台，采用 Java 21 + Spring Boot 构建模块化业务后端，Python FastAPI + LangGraph 构建独立 AI 服务，Vue 3 实现用户端、客服工作台和管理端。系统支持仅退款、退货退款、换货和维修流程，通过 RAG 检索售后政策、Tool Calling 查询订单/物流/质保，并以“AI 生成提案、Java 校验确认后执行”的方式隔离模型幻觉与核心交易数据。

完成项目后才能使用的量化描述必须来自真实测试结果，不要提前写“提升 80%”或“支持 10 万 QPS”。

## 2. 可写亮点（实现后选择）

- 设计 Java/Python 双服务边界，Python 无业务库写权限；高风险售后操作由 Java 状态机、资格规则和事务统一执行。
- 使用 `Idempotency-Key + request hash + 数据库唯一约束 + 乐观锁` 防止重复确认导致重复退款。
- 通过 Transactional Outbox + RabbitMQ 实现工单分析、文档索引和结案摘要的可靠异步处理，并处理重复消费与 DLQ。
- 构建带元数据过滤和引用溯源的 Qdrant RAG，使用标注集评测 Recall@K、引用准确性和无答案拒答。
- 使用 Python SSE → Java 校验代理 → Vue 流式渲染，统一完成鉴权、审计、取消和 AI 故障降级。
- 基于模型 usage 记录 Token 和预算，在 40/50 元阈值实施告警与硬限制。

## 3. 面试必须能回答

### 为什么不用全 Java/Spring AI？

Java 更适合本项目确定性业务、事务、权限和状态机；Python 的文档解析、RAG、LangGraph 和模型生态更成熟。拆分不是为了微服务数量，而是为了能力与安全边界。Python 失败时 Java 工单仍可人工处理。

### 为什么 AI 不能直接退款？

LLM 输出不稳定，可能幻觉、被提示注入或重复调用。AI 只生成结构化提案；Java 重新查询订单、计算金额、校验状态和权限，并在幂等事务中执行。

### 如何防重复退款？

前端重试复用 Idempotency-Key；Java 保存 request hash，相同 Key 不同请求拒绝；`proposal_execution.proposal_id/idempotency_key` 唯一；事务中锁定提案并校验版本，最终只有一个执行记录成功。

### 为什么使用 Outbox？

如果先提交工单再发 MQ，进程可能在两步之间崩溃；如果先发 MQ 再提交，消费者可能读不到工单。Outbox 与工单同事务写入，再由后台可靠发布，实现最终一致性。

### RAG 如何减少幻觉？

检索时做有效期和商品范围过滤，回答展示引用；没有足够证据时转人工。RAG 不能从根本保证正确，所以最终资格仍由 Java 规则决定，并通过评测集持续验证。

### SSE 为什么经过 Java？

浏览器只有一个可信入口；Java 负责用户/工单权限、内部签名、事件白名单、审计和消息持久化。代价是 Java 需要正确处理背压、取消和超时。

### RabbitMQ 和 SSE 是否重复？

不重复。MQ 处理无需用户等待的可靠异步任务；SSE 用于用户正在等待的实时 token 流。

### 为什么不用微服务？

四周个人项目中，商品、订单、工单和提案共享强事务边界，模块化单体更容易保证一致性和完成度。Python AI 因技术栈、资源和故障边界独立部署。未来流量和团队边界明确后再拆 Java 服务。

## 4. 演示顺序

2～3 分钟视频：

1. 用户查看耳机订单并提交故障工单。
2. 客服工作台收到自动分配，展示 AI 分类、缺失信息和政策引用。
3. 客服编辑回复并发布仅退款/退货方案。
4. 用户确认，展示 Java 执行、状态时间线和审计记录。
5. 重复点击确认，展示不会重复执行。
6. 暂停 AI 服务，展示人工流程仍然可用。
7. 简短展示架构图、评测结果和 Docker 部署。
